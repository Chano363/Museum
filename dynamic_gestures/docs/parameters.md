# 动态参数调整文档

## 概述

本项目支持运行时动态调整关键参数，无需重启应用程序。通过 ConfigManager 和 DynamicConfigManager 类，系统可以实时监控配置文件的变化并应用新参数。

## 动态参数机制

### 配置管理器 (ConfigManager)

ConfigManager 是核心配置管理类，负责：
- 从 JSON 文件加载配置参数
- 实时验证参数的有效性
- 线程安全的参数访问
- 提供回调函数接口以响应参数变化

### 动态配置管理器 (DynamicConfigManager)

DynamicConfigManager 扩展了基本功能，增加了：
- 文件系统监控，自动检测配置文件变化
- 信号处理，支持通过 SIGUSR1 信号触发配置重载
- 实时参数更新机制

## 支持的动态参数

### 1. batchSize
- **类型**: 整数
- **默认值**: 1
- **范围**: 1-128
- **用途**: 设置模型推理的批量大小，影响性能和内存使用

### 2. inputSize
- **类型**: 整数
- **默认值**: 224
- **范围**: 32-1024
- **用途**: 设置输入图像尺寸，影响模型推理速度和精度

### 3. threads
- **类型**: 整数
- **默认值**: 2
- **范围**: 1-16
- **用途**: 设置并发线程数，影响多线程处理能力

### 4. precision
- **类型**: 字符串
- **默认值**: "int8"
- **可选值**: "fp32", "fp16", "int8", "int4"
- **用途**: 设置模型推理精度，影响性能和准确性

### 5. confidence
- **类型**: 浮点数
- **默认值**: 0.5
- **范围**: 0-1
- **用途**: 设置手部检测置信度阈值，过滤低质量检测结果

### 6. iou_threshold
- **类型**: 浮点数
- **默认值**: 0.3
- **范围**: 0-1
- **用途**: 设置跟踪关联的交并比阈值，影响跟踪连续性

### 7. max_age
- **类型**: 整数
- **默认值**: 30
- **范围**: 1-100
- **用途**: 设置跟踪对象的最大未检测帧数，超过此值则删除跟踪

### 8. min_hits
- **类型**: 整数
- **默认值**: 3
- **范围**: 1-20
- **用途**: 设置确认跟踪对象所需的最小检测次数，减少误跟踪

### 9. fps_limit
- **类型**: 整数
- **默认值**: 0 (无限制)
- **范围**: ≥0
- **用途**: 设置最大帧率限制，用于控制处理速度

## 参数更新机制

### 文件监控
系统会监控配置文件 (configs/remote_debugger_config.json) 的变化。当文件被修改时，系统会自动重新加载并应用新参数。

### 信号触发
发送 SIGUSR1 信号到进程也可以触发配置重载：
```bash
kill -SIGUSR1 <pid>
```

### 回调机制
set_config_change_callback() 函数允许注册回调函数，在配置改变时执行特定操作，如重新初始化控制器。

## 在主控制器中的应用

当配置发生变化时，MainController 会被重新初始化，使用新的参数值：

- max_age: 控制跟踪器的最大未更新时间
- min_hits: 控制跟踪器确认所需最小命中次数
- iou_threshold: 控制目标关联的匹配阈值
- confidence: 控制检测模型的置信度阈值

## 配置文件格式

配置文件应为标准 JSON 格式：

```json
{
  "batchSize": 1,
  "inputSize": 224,
  "threads": 2,
  "precision": "int8",
  "confidence": 0.5,
  "iou_threshold": 0.3,
  "max_age": 30,
  "min_hits": 3,
  "fps_limit": 0
}
```

## 重要文件

以下是与动态参数调整相关的关键文件：

### 核心配置管理
- config_manager.py: 实现配置管理的核心文件，包含 ConfigManager 和 DynamicConfigManager 类
- configs/remote_debugger_config.json: 默认的配置文件模板

### 主要应用文件
- run_demo.py: 主演示脚本，实现了动态配置的回调函数和使用
- main_controller.py: 主控制器，接收并使用动态配置参数

### 相关组件
- onnx_models.py: 包含模型推理，其中置信度阈值可动态调整
- ocsort/association.py: 跟踪关联模块，使用iou_threshold参数
- ocsort/kalmanboxtracker.py: 卡尔曼跟踪器，受max_age和min_hits参数影响

## 开发要点

### 1. 参数验证机制
所有参数在加载时都会经过验证，确保其类型和范围符合要求。超出范围的值会被替换为默认值。

### 2. 线程安全
使用 threading.Lock() 确保配置访问的线程安全性，防止并发访问导致的数据竞争。

### 3. 回调函数设计
通过回调机制可以在配置更新时执行特定操作，如重新初始化 MainController。

### 4. 实时监控
使用 watchdog 库监控文件系统事件，实现配置文件的实时更新。

### 5. 错误处理
系统在加载配置失败时会使用默认配置，并记录错误日志。

### 6. 信号处理
支持通过 SIGUSR1 信号触发配置重载，提供另一种动态更新方式。

## 注意事项

1. 参数验证会在加载时自动进行，超出范围的值将被替换为默认值
2. 修改参数后，系统会输出日志信息确认参数已更新
3. 某些参数（如 inputSize）的大幅变更可能会影响模型性能
4. 建议在生产环境中谨慎调整跟踪相关参数（如 max_age, min_hits）
5. 在开发过程中，建议通过日志监控配置更新是否成功应用

## 故障排除

如果配置更新没有生效，请检查：
- 配置文件路径是否正确
- JSON 格式是否有效
- 是否有权限读取配置文件
- 日志中是否有错误信息
- 监控服务是否正常运行
